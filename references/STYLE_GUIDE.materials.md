# 本地资料成书：整理规范模板

> **这是一份模板，不是成品。**
> 适用于「给一个装满资料的本地目录（讲义 PDF/docx + 扫描件 + 课堂记录），整理成一本系统的书」。
> 复制到你的项目里（如 `<项目根>/book8/STYLE_GUIDE.md`），按下面各节把占位符换成你的内容。

---

## 一、缘起与定位

把 `<资料目录>` 下的资料（讲授者讲授的系列讲义 + 课堂记录 + 笔记）编纂成一本**由入门到基础的系统读本**。

- 目标读者：零基础到入门。
- 体例上**按知识体系重排**，不按原始资料的课堂时序。
- 整理人署名：`<整理者>`（**不等于讲授者**；不署讲授者时封面只写「整理者　整理」）。

**先想清楚三件事**（写进本节，后面所有脚本都依赖它）：

1. **主干是什么**——哪几份资料体系完整、条理清晰（当骨架）。
2. **血肉是什么**——哪几份是课堂实录/案例集（当细节与实例）。
3. **成品规模**——多少编、多少章、每章多少字。

## 二、源材料清单（`materials/`）

开工第一步是**盘点家底**（方法见 SKILL.md 第九节）。盘点完把结果写成一张表，注明哪份是主源：

```
| 文件 | 字数 | 定位 |
|---|---|---|
| <主源文件> | <字数> | **主源**（体系完整，当骨架） |
| <讲座/实录文件> | <字数> | 实例素材（当血肉） |
| <归纳表/附录文件> | <字数> | 作正文附表引用 |
| <扫描件> | — | 无文字层，走 OCR（见第九节） |
```

合计可用文字约 `<总数>` 字。**扫描件与电子版的区分、加密 PDF 的处理**见 SKILL.md 第九节。

## 三、成书结构（三级大纲：编 → 章 → 节）

```
# <书名>                        ← H1
## 第一编　<编名>                ← H2（编）
### 第一章　<章名>               ← H3（章）
（章内用自然段分节，节标题用「一、」「二、」起段）
```

- **编**：若干编，各带一句编前说明（排在同一张扉页下半部）。
- **章**：每章独立成稿，文件名 `sec-md/<前缀>-NNN.md`，首行 `## 第N章　章名`（章内小标用「二、」等纯文本）。
- 每章目标 `<X>~<Y>` 字，全书目标 `<总数>` 字。
- 骨架写进合并脚本的 `VOLUMES = [(编名, 编前说明, [章号…]), …]`，脚本可重入。

## 四、全书目录

写在这里，作为**骨架的唯一事实来源**（改结构先改这里，再改合并脚本）：

```
**第一编　<编名>**
- 第一章　<章名>（<本章小节>）
- 第二章　…
**第二编　<编名>**
- …
```

- 编名、章名要与合并脚本、排版脚本里的书名严格一致。
- 书出版后若做过「体系抽离」（把某一支内容抽成姊妹册），这里要注明正文不含哪些章，以及抽走的内容去哪了。

## 五、写作要求

1. **纯文本、无列表、无加粗**；正文用自然段。章内如需分点，用「一、」「二、」「（一）」「①」等中文序号起段。
2. 每章末可附「本章小结」一段（不加标题以外的修饰）。
3. **术语规范**：把本领域的术语写法写死在这里（哪些用全称、哪些保留本门简写、哪些必须按参考文本逐字核对）。**术语是这类书最容易出错的地方**，宁可写得啰嗦。
4. **错字与口语渣**：源资料是课堂记录时有大量口语、重复、断句混乱、同音错字。整理时**删口语、并重复、补断句**，保留全部知识点与判断逻辑。
5. **人名、公司名、地名一律泛化**（「某总」「某学员」「某地」）；但**专业数据（数值、日期、编号、结论口径）一律照实保留**。
6. 涉及疾病、灾祸、纠纷等的具体描述保留（这是知识点），但避免渲染细节。
7. **引文与口诀照录，不改字**（用中文引号）。
8. 不评价、不引申当代政治人物。
9. 若做过「体系抽离」（正文只留主干，某一支另成姊妹册），在第一条就声明：正文以什么为主、不出现什么框架、用到时怎么表述。**这条要写得像法律条文一样明确**，否则子代理会把抽走的框架又写回来。

## 六、校验口径

- 每章 `## ` 数量 = 1（章标题），无 `### `、无 `**`、无行首 `- ` 或 `* `。
- 术语错字零残留（对照第五节与第八节的表）。
- 无报道腔（「他指出」「据了解」「如上所述」）。
- 专业数据核对无误（**来源照抄，不自行推算**）。
- 若声明了体系抽离：抽走的关键词在正文里 `grep -c` 必须为 0。

## 七、常见错字对照表（通用）

```
| 源资料 | 正确 | 说明 |
|---|---|---|
| 己经 | 已经 | |
| 因该 | 应该 | |
| 以经 | 已经 | |
| <领域专有名词的同音误写> | <正确写法> | 按参考文本核对 |
| <本门术语简写> | <规范全称> | 正文首次出现用全称，后文可简称 |
```

**维护方式**：边整理边补。子代理报回来的新错字、新术语变体，立刻追加进表——这张表是下一批子代理的输入，补得越快，后面越省事。

## 八、OCR 扫描件专用：数值纠错（若资料来源含扫描件）

扫描件 OCR 对**易混字形**误识严重（相近的数字、字母、汉字部件），写稿时必须逐字纠正。做法：

1. 建一张「OCR 误识 → 正确」对照表，把本领域的高频误识列全（数字、单位、专有符号）。
2. **三重校验法**（每一处关键数据都过一遍）：
   - **内部一致性**：同一组数据内部必须自洽（如编号、日期、编号区间，格式错一位就必有一处误识）。
   - **白名单校验**：每个值必须落在本领域的合法取值集合内（对照标准表、编号表、术语表）。
   - **跨文件互校**：同一内容在多个来源重复出现时，互相校对；有疑问的**回原页核对**，不要凭印象改，也不要照抄 OCR 错字。
3. 结论：**凡有疑问，一律回原文件原页核对。**

## 九、交付

- `present_files` 一次给全：`docx` + `pdf`（+ `md`）。
- PDF 页码是印死的，翻着最方便，优先给用户 PDF。
- 附「整理前后」对照图（批量重排前先把旧 docx 备份到 `_old_docx/`，否则做不出真实对照）。
